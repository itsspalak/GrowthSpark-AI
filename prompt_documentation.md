# Prompt Documentation — GrowthSpark AI: Campaign Lab

## Project goal
Create one practical technology-domain project for the AI Growth & Automation Associate assessment. The chosen area is digital marketing: a campaign-planning prototype that converts a small set of product and audience inputs into a structured growth plan.

## Prompt 1 — Idea selection and problem framing
> I need one demonstrable project for an AI Growth & Automation Associate assessment. Suggest a creative but achievable technology-domain project in digital marketing or automation. It should solve a real growth problem, be interactive in a browser, and produce a concrete output rather than just describing an idea.

**Use:** Narrowed the scope to a campaign-planning lab instead of a generic chatbot.

## Prompt 2 — Define the MVP
> Turn the campaign-planning idea into a small MVP specification. Include target user, problem, input fields, outputs, core workflow, and practical value. Keep the first version usable without accounts, paid APIs, or secret keys.

**Use:** Defined product/audience, goal, channel, budget, duration, and customer insight as inputs, with campaign angles, experiments, KPIs, and an execution plan as outputs.

## Prompt 3 — UI and interaction
> Build a responsive single-page web app called GrowthSpark AI — Campaign Lab. Use a modern dark interface with strong contrast and a restrained neon-lime accent. Include clear input controls, a generate action, campaign strategy output, experiments, KPIs, and execution steps. Make the page usable on desktop and mobile.

**Use:** Guided the page structure and visual direction.

## Prompt 4 — Make the output actionable
> Add front-end logic so the selected growth goal, channel, budget, duration, product, audience, and customer insight influence the campaign plan. Present three experiments with a hypothesis and metric, and include copy/download actions for the resulting plan.

**Use:** Focused the output on actionable experiments and measurable outcomes rather than vague marketing copy.

## Prompt 5 — Improve readability with dark theme
> Convert the interface to a polished dark theme. Use charcoal backgrounds, readable text, distinct cards, clear borders, and neon-lime highlights for important actions. Preserve all existing functionality and ensure contrast remains readable.

**Use:** Produced the final dark-theme presentation.

## Prompt 6 — Review transparency and limitations
> Review the prototype description and documentation for misleading AI claims. Clearly distinguish AI-assisted development from live AI inference. State whether the browser app calls a live model or external service, explain local processing, and list sensible next steps for a production version.

**Use:** Added an explicit limitation statement: outputs are generated by predefined JavaScript rules/templates and no live LLM is connected.

## Iteration notes
- The project was narrowed from a broad AI/growth concept to a specific campaign-planning workflow.
- The output was structured into campaign angles, experiments, KPIs, and execution steps so it is easier to evaluate and demonstrate.
- A dark theme was applied for clearer visual hierarchy and a more finished demo.
- The implementation was kept local and dependency-free so an assessor can run it without credentials.

## Manual testing checklist
- [ ] Open `index.html` directly in a current browser.
- [ ] Generate a plan with the default or sample values.
- [ ] Change the growth goal and confirm the plan changes where supported.
- [ ] Change the channel and confirm the plan reflects the selection where supported.
- [ ] Change budget and campaign duration.
- [ ] Add a customer insight and check that it is reflected in the generated plan.
- [ ] Confirm three experiment ideas, KPIs, and execution steps are visible.
- [ ] Test the copy-plan action.
- [ ] Test the download-plan action.
- [ ] Test at a narrow/mobile viewport.
- [ ] Confirm the limitation note does not claim a live LLM integration.

## Transparency note
This document records the prompts used to frame, specify, and refine the deliverable. The shipped prototype does not send these prompts to a live language model at runtime. Its campaign generation uses predefined front-end logic and templates. If a live model is added later, document the actual runtime prompts and secure API architecture separately.
